# Trajectory GitHub App

Trajectory presents repository-authored implementation choices on an issue, applies the selected file replacements, checks JSON values, and publishes a branch and draft pull request on request. It does not merge pull requests.

This version runs bounded transformations authored in the repository's `.trajectory.json`. It does not execute arbitrary model output, repository scripts, or application code. Its checks compare top-level JSON object values; a passing receipt establishes those comparisons, not application behavior.

## Run the service

Build with Go 1.22 or newer:

```sh
go build -o trajectory-app ./cmd/trajectory-app
export TRAJECTORY_PUBLIC_URL=https://trajectory.example.com
export TRAJECTORY_ADDR=127.0.0.1:8081
export TRAJECTORY_STATE_DIR="$HOME/.local/state/trajectory"
export TRAJECTORY_SETUP_TOKEN='a-long-random-bootstrap-password'
./trajectory-app
```

Put an HTTPS reverse proxy in front of the process, routing to the configured address. `TRAJECTORY_PUBLIC_URL` must be an HTTPS origin with no path, query, fragment, or embedded credentials. The service exposes:

| Route | Purpose |
| --- | --- |
| `GET /healthz` | Process health; returns `ok` even in setup mode. |
| `GET /setup` | HTML form containing the GitHub App manifest. |
| `GET /setup/callback` | Validates registration state, exchanges GitHub's code, and saves credentials. |
| `POST /webhook` | Signed GitHub webhook delivery; unavailable until credentials are configured. |

## Register and install

Open your public URL followed by `/setup` in a browser, authenticate with username **trajectory** and your `TRAJECTORY_SETUP_TOKEN` password, and select **Register on GitHub**. Both setup routes require this administrator password; registration is disabled when the token is absent. Choose a unique app name on GitHub. GitHub returns to this service with a temporary registration code; the service checks the browser's random state cookie, exchanges the code directly with GitHub, and saves the returned App ID, private key, webhook secret, and app slug in `TRAJECTORY_STATE_DIR/credentials.json` with mode `0600`. It refuses to overwrite an existing credential file. The callback displays the installation link and restart instructions, without displaying or logging the code or credentials.

Restart the process with the same state directory to load the saved credentials automatically, then follow the installation link and select the repositories the app should handle. You can remove `TRAJECTORY_SETUP_TOKEN` after registration to disable the setup routes. The manifest creates a private app owned by the account registering it. Start setup and finish the callback in the same browser within ten minutes; its cookie requires your public HTTPS URL.

The generated manifest uses these settings:

| Setting | Value |
| --- | --- |
| Homepage URL | Your `TRAJECTORY_PUBLIC_URL` |
| Webhook URL | Your `TRAJECTORY_PUBLIC_URL` followed by `/webhook` |
| Webhook active | Enabled |
| Webhook secret | Generated by GitHub during registration |
| Repository metadata permission | Read |
| Repository issues permission | Read and write |
| Repository contents permission | Read and write |
| Repository pull requests permission | Read and write |
| Repository checks permission | Read and write |
| Subscribed events | Issues, Issue comment, and Check run |

The form posts its manifest to `https://github.com/settings/apps/new` and follows GitHub's [documented manifest registration flow](https://docs.github.com/en/apps/sharing-github-apps/registering-a-github-app-from-a-manifest), including the server-side code exchange. No real GitHub registration is performed by local tests; they use an HTTP test server.

You can alternatively register an app manually under **GitHub Settings → Developer settings → GitHub Apps → New GitHub App**, using the table above and your own webhook secret. Save its **App ID**, generate and securely save its **private key**, install it on the target repository, and supply all three environment variables:

```sh
export TRAJECTORY_APP_ID=123456
export TRAJECTORY_PRIVATE_KEY_FILE=/secure/path/trajectory.pem
export TRAJECTORY_WEBHOOK_SECRET='your-saved-webhook-secret'
export TRAJECTORY_STATE_DIR="$HOME/.local/state/trajectory"
./trajectory-app
```

The explicit credential variables take precedence over saved credentials; supply all three or omit all three. The process reads the raw PEM file and does not use a personal access token. Keep credentials outside the repository and restrict access to the service account. Persist `TRAJECTORY_STATE_DIR` across restarts; it stores credentials, queued work, and issue state. Run one service process for a state directory. If neither saved credentials nor credential variables exist, setup mode starts. Partial credential configuration fails startup. The default state directory is `./trajectory-state`; the default listen address is `127.0.0.1:8081`.

If a reverse proxy records request URLs, exclude callback query strings from its access logs. The app itself does not log callback query parameters, upstream response bodies, or credential values.

## Prepare the subscription example

Use a dedicated demo repository on which the app is installed. From this project's root, copy all three example files to that repository's root:

```sh
cp examples/subscription/.trajectory.json examples/subscription/access.go examples/subscription/subscription.json /path/to/installed-repository/
```

Commit all three files to the default branch. The config includes SHA-256 preimages for both starting files, including their final newlines. Reformatting or changing either starting file requires updating its digest in both choices.

Open an issue asking how cancellation should affect access and add the `trajectory` label as a repository writer. The app posts a decision comment. Select exactly one checkbox; to change a choice before publishing, clear the previous checkbox first. Multiple selections invalidate the preview and the app asks you to clear the extra checkbox. The app checks the current comment before acting on an edit and binds approval to the patch shown in its preview.

`keep` changes `HasAccess` in `access.go` to return `now < paidUntil`, allowing access before the paid-through boundary. `end` makes `HasAccess` return `false`, revoking access immediately. Both also replace `subscription.json` with the corresponding cancellation state. The app checks the declared JSON values and file preimages; it does not execute the Go code or claim those comparisons prove the behavior.

Review the resulting diff and select **Open draft pull request** in the preview comment. The app creates a branch and a draft PR. Before creating the PR check, the app reads the PR head and verifies that its complete tree contains only the selected patch on the pinned base. The PR's **Checks** tab shows a neutral **Trajectory decision** check with two actions: **Revalidate** checks the pinned inputs, PR tree, preimages and declared JSON assertions again and updates the same check; **Post decision** posts the decision receipt on the issue. Both require repository write access. If an action cannot complete after retries, the app reports the reason on the associated issue, retrying the notification if GitHub is temporarily unavailable. If the issue, base, or PR head changes, start a fresh decision instead of relying on the old result. Publishing does not merge the PR.

To compare outcomes, start from the same unchanged baseline in two separate issues. Select `keep` in one and `end` in the other; review the different patches and receipts.

For local behavioral qualification of the example, run this from this project's root:

```sh
python3 scripts/qualify-app-example.py
```

This local script applies each declared replacement in a temporary directory, checks its preimage and JSON values, and runs Go tests for access before and at the paid-through boundary. It runs separately from the GitHub App. The app does not execute this script or arbitrary repository commands.

## Author repository choices

The config has this shape:

```json
{
  "version": 1,
  "question": "Which outcome should the patch implement?",
  "choices": [
    {
      "id": "choice-id",
      "title": "Describe the outcome",
      "changes": [
        {"path": "state.json", "before_sha256": "<SHA-256 of existing bytes>", "content": "{\"enabled\":true}\n"}
      ],
      "checks": [
        {"path": "state.json", "key": "enabled", "equals": true}
      ]
    }
  ]
}
```

Use repository-relative file paths and SHA-256 digests of the existing file bytes. `content` is the full replacement, not a diff. Each `key` names a literal top-level key of a JSON object, and `equals` is its expected JSON value. For example, `enabled` compares a boolean; a dotted key does not traverse nested fields.

Changes cannot target `.git`, `.github`, or `.trajectory.json`. A choice cannot alter its own config or GitHub workflow files. Keep alternatives understandable from their title and resulting diff, and give each outcome checks that distinguish it from the other options.
